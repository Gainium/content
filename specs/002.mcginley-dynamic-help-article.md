# 002. McGinley Dynamic help article

Feature spec — a new content article, no existing behaviour is being
changed. Closes the gap the other three repos' plans already named: the
dashboard's indicator catalog links to `/help/mcginley-dynamic`, and until
this article exists that link is dead and the RAG/AI assistant has
nothing to cite about the indicator (per `CLAUDE.md`'s "What it OWNS/
EMITS" — main-app's RAG and public-frontend both consume this API).

## §1 Behaviour

- A markdown file at `docs/help/mcginley-dynamic.md` with frontmatter
  satisfying `REQUIRED_HELP_FIELDS` (`src/contentLoader.ts`): `id`, `name`,
  `slug`, `description`, `createdAt`, `updatedAt`, `publishedAt`,
  `locale`, `categories`.
- `slug: mcginley-dynamic` — must match exactly what `main-dash-sh`'s
  `indicatorCatalog.ts` `INDICATOR_DOCUMENTATION_URLS[IndicatorEnum.mg]`
  points at (`/help/mcginley-dynamic`), confirmed against that repo's
  already-committed plan.
- Content explains what the indicator computes, how to configure it in
  Gainium (mirroring the actual bot-settings fields — length, interval,
  condition, value; per `app-sh`'s spec, McGinley reuses the generic
  threshold fields, not `ma`'s bespoke crossing fields), and at least one
  example bot-trading strategy — matching the depth/structure of the two
  closest existing articles, `atr.md` (same field shape: length/interval/
  condition/value, no bespoke fields) and `long-wick-detector.md` (the
  most recently added article, same "new indicator" provenance).

## §2 Open questions

- **Numeric `id`.** Existing help docs range up to `1040`; `id` isn't
  used as a lookup key (`ContentLoader` indexes by `slug`, confirmed by
  reading `parseHelpDoc`), so a collision wouldn't break lookup, but
  picking an unused number is still the right default. Resolved: `1041`.
- **`ingested`/`ingestedAt`.** `atr.md` (`ingested: true`, dated) is an
  already-RAG-processed article; `long-wick-detector.md` (`ingested:
  false`, `ingestedAt: ''`) is the precedent for a brand-new article not
  yet run through that pipeline. Resolved: follow `long-wick-detector.md`
  — `ingested: false`, `ingestedAt: ''`.
- **`categories`/`tags`.** `atr.md` uses `categories: [technical-indicators]`,
  `tags: []`; `long-wick-detector.md` uses the same category plus `tags:
  [indicator, smart-money-concepts]` (its specific analytical niche).
  McGinley Dynamic is a plain moving-average variant with no
  specialised-analysis angle, so it follows `atr.md`: `categories:
  [technical-indicators]`, `tags: []`.

## §3 Non-goals

- No change to `src/contentLoader.ts`, `src/types.ts`, or any code in this
  repo — `REQUIRED_HELP_FIELDS` and the loading/indexing logic already
  handle an arbitrary new help doc with no per-article code.
- No change to `main-app`'s RAG functions or `public-frontend`'s content
  client — both are generic consumers of this repo's `/help/:slug` API;
  a new article needs no code there, only content (matches the "the three
  external consumers themselves need no per-indicator code" pattern the
  new-indicator-integration skill already established for the platform's
  other generic-consumer layers).
