# 002. McGinley Dynamic help article — plan

Implements [specs/002.mcginley-dynamic-help-article.md](../specs/002.mcginley-dynamic-help-article.md).

## Build order

1. `docs/help/mcginley-dynamic.md` — frontmatter per spec §1/§2 (`id:
   1041`, `slug: mcginley-dynamic`, `categories: [technical-indicators]`,
   `tags: []`, `ingested: false`), body structured like `atr.md`
   (what it is → how to configure the actual Gainium fields → strategy
   examples → practical considerations → conclusion), since McGinley
   Dynamic shares `atr.md`'s exact field shape (length/interval/
   condition/value, no bespoke fields) rather than `long-wick-detector.md`'s
   (which documents bespoke fields McGinley doesn't have).
2. No code changes (spec §3).

## Contract decisions the spec left open (§2)

- `id: 1041` (next unused after the current max, `1040` — not load-bearing
  since lookup is by `slug`, but kept unique as good practice).
- `ingested: false`, `ingestedAt: ''` — matches `long-wick-detector.md`'s
  precedent for a brand-new, not-yet-RAG-processed article.
- `categories: [technical-indicators]`, `tags: []` — matches `atr.md`
  (no specialised-analysis angle the way Long Wick's `smart-money-concepts`
  tag has).

## Blast Radius

1. **Other call sites** — none; this repo's loader (`src/contentLoader.ts`)
   discovers help docs generically by scanning `docs/help/*.md` (confirmed
   by reading `loadAllContent`), so a new file needs no registration
   anywhere in code.
2. **`core/` submodule** — N/A, this repo has none.
3. **Contract surface this repo's `CLAUDE.md` documents as owned** — the
   `/help/:slug` REST shape is the contract `main-app`'s RAG and
   `public-frontend` consume. This change is purely additive (a new slug,
   no change to the JSON shape or existing slugs), so no existing
   consumer's behaviour changes.
4. **Duplicate slug** — `parseHelpDoc` explicitly rejects a duplicate slug
   (logs an error, skips the file) — confirmed `mcginley-dynamic` isn't
   already used by grepping every existing `docs/help/*.md`'s `slug:`
   field.
5. **The other three repos' named gap, now closed** — `indicators`,
   `app-sh`, and `main-dash-sh`'s plans all flagged this article as
   out-of-scope/not-yet-authored. This PR closes that gap; the dashboard's
   `/help/mcginley-dynamic` link will resolve once this merges and
   deploys.

## Test idiom

This repo uses mocha + chai (`npm test`), per `package.json`'s `"test"`
script and `test/placeholder.spec.ts`. `test/mcginleyDynamic.spec.ts`
exercises the real `ContentLoader` class against the real file on disk
(an integration-style test, not a hand-rolled frontmatter parse) so it
catches the same failure modes the live service would.
