# New indicator integration — content's part

Canonical source: `new-indicator-integration` in Gainium's internal
`skills` repo (private — this file is a scoped copy synced from there; edit
the source, not this copy, if it needs updating).

## Global objective

Gainium's indicator math is written once and consumed across the bot
engine, backtester, market-archive, and the dashboard chart. None of that
helps a user understand what the indicator actually does or how to
configure it — this repo is that explanation, and it's also what the
in-app RAG/help assistant reads from when a user asks about the indicator.

## This repo's part

An indicator page, `docs/indicators/<slug>.md` (spec 053: indicators are
their own content type, served at `/indicators/<slug>` by this API and at
`https://gainium.io/indicators/<slug>` by the site). The dashboard catalog's
`INDICATOR_DOCUMENTATION_URLS` keeps the in-app route `/help/<slug>`, and
the Help Center resolves it through `/indicators`.

Before writing, read `docs/STYLE.md`: the style rules and "The indicator
article template (`templateVersion: 2`)". Copy the shape of a finished page
such as `docs/indicators/atr.md`. `npm run check:indicators` holds every
rule below in CI.

- **Existing page?** If the indicator already has a page as a
  TradingView-only indicator (`kind: builtin` or `community`), keep the
  page and its URL: flip it to `native`, add `catalogKeys`, and replace its
  webhook recipe with the bot-form steps, in the same release as the
  dashboard.
- **Frontmatter**: `id`, `name`, `slug`, `description`, `createdAt`,
  `updatedAt`, `publishedAt`, `locale`, `categories` are all required (a
  doc missing one is skipped without an error), plus `templateVersion: 2`,
  `kind: native`, `catalogKeys` (the `IndicatorEnum` values), `category`,
  `aliases`, `related` and `faq` (3–5 `{title, details}`, plain text).
  `id` = the highest `id` across `docs/help` and `docs/indicators` + 1.
  Quote the dates.
- **Body**: an opening of 2–3 sentences, then exactly `## What is <Name>`
  (optionally ending in `### Settings and tips`), `## Trading setups for
  bots` (2–4 setups with Entry / Exit / Settings / Timeframe / When it
  fails), `## Using <Name> in Gainium` (bot-form steps, each catalog field
  with its default) and `## Related indicators` (≥2 links to
  `https://gainium.io/indicators/<slug>`). No `#` title, no `## FAQ`.
- **Settings table**: generated. `npx tsx scripts/describe-native.ts <slug>
  --write` writes `<slug>.settings.json` from the catalog (set
  `INDICATOR_CATALOG_PATH` to the feature checkout's `indicatorCatalog.ts`
  before main-dash-sh is pushed); paste its `--format md` table and write
  only the "What it does" cells. Field names must match `main-dash-sh`'s
  catalog entry, not your reading of the math.
- **Edge (spec 054)**: add `<slug>.edge-recipe.json` (shape:
  `rsi.edge-recipe.json`). `<slug>.edge.json` is generated by
  claus-dashboard's indicator-edge engine and refreshed by its monthly job;
  never write it by hand.
- **Chart approximation**: if Step 0's Pine Script portability check
  flagged a gap, say so plainly in "What is".
- **Images** under `docs/images/indicators/<slug>__<shot>.{png,webp}`,
  embedded as
  `https://content.gainium.io/images/content/indicators/<slug>__<shot>.webp`,
  alt text saying what each shows. TradingView charts: claus-dashboard's
  `tv-capture`/`tv-tip`, annotated with the `annotate-image` skill. Bot
  form: the `gainium-docs-screenshots` indicator recipe, run from the
  feature checkout before deploy. Open each image before committing — a
  valid image of the wrong screen exits successfully.

The content API also serves `public-frontend` and feeds main-app's RAG and
Max, so a missing page means both a dead help link **and** the AI assistant
having nothing to cite about this indicator.

## Sister repos

All public, same repo family as this one:

- **indicators** — the math this doc explains; not code this repo touches.
- **backtester** — unrelated to this repo's docs work.
- **app-sh** — unrelated to this repo's docs work directly, though the
  AI agent it exposes via the v2 API contract is a consumer of what this
  repo publishes.
- **main-dash-sh** — owns the catalog entry whose help-URL slug must match
  what this repo publishes at — confirm the exact slug before or right
  after writing the page.

Gainium's main-app and dashboard services (both ship as part of the
self-hosted bundle too) read from this repo's published content the same
way regardless of deployment — nothing self-hosted-specific to do here.
